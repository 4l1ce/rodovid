# Case notes format

One markdown note per working session or sub-question, kept in the
person's project (or files) so the next session starts where this one
ended. Title: `<Лінія/місце> — <питання або знахідка> (<дата>)`.
The evidence ledger (xlsx) is saved next to it with the same title stem.

```
# <Лінія> — <питання> (<DD.MM.YYYY>)

<дата> · <хто> · продовження нотаток «…» (не повторювати перевірене там)

Позначки: скан — відкрито зображення; індекс — лише індекс; перевірено —
незалежно перечитав верифікатор (або людина). Рівні: підтверджено /
ймовірно / гіпотеза / не знайдено — інших немає.

## Головне
1. <знахідка або висновок, з рівнем і посиланням>
2. …

## <Підпитання>
| Хто | За записом (дослівно) | Скан / індекс | Джерело |
|---|---|---|---|

Висновок: <ланцюг доводів>; рівень: <гіпотеза/ймовірно/підтверджено>.

## Аномалії й суперечності
| Запис | Що не сходиться | Як пояснити / що перевірити |

## Відкинуті кандидати
| Хто | Чому не він | Джерело |

## Перевірка
| Запис | Перший читач | Верифікатор | Збіг? |
Що не перевірено і чому (немає браузера, агент недоступний тощо).

## Реєстр доказів
<таблиця з ledger.py export-md>; файл: <назва>.xlsx

## Карта джерел (оновлення)
| Справа | Що | DGS / посилання | Стан |

## Що лишилося
**Онлайн:** - [ ] … (з номерами знімків, де зупинились; які пошукові
запити не завершено)
**Запит до архіву:** 1. …

## Дерево
<що змінено за згодою / що можна змінити — лише перевірене або з позначкою «гіпотеза»>
```

Rules: every factual line has a source (ф.-оп.-спр., image, link);
corrections to earlier notes go in a «Виправлення» section, never by
silently rewriting old notes; record decisions the person made
("закрито: не шукати далі …") so future sessions respect them.
